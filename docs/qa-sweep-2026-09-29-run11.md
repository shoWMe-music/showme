### [MAJOR] Deals — a deal's figures can be rewritten after one party has signed, and their signature is kept on the new document
**As:** `agent@` (Astra Booking, acting for Marlo Vance), against a deal `operator@` had already signed.
**Steps:**
1. As `operator@`, create `QA11 Money Night` through the wizard with a `guarantee_vs_door` deal, guarantee **SEK 60,000** / 70%.
2. As `operator@`, Deals tab → **Confirm your line**. Card reads *"Sent — awaiting confirmations · 1 of 2 signed"*.
3. Switch seat to `agent@`. Deals tab → **Edit figures** → change FIXED AMOUNT to **90,000** → *Save the figures*. No warning, no re-signature prompt.
4. **Confirm your line** as the agent. Card goes to *"Confirmed — terms frozen"*.

**Expected:** either the operator's signature is torn up (that is what `POST /deals/:id/reopen` is
for, and the Deals tab offers it), or the edit is refused. `useEventAgreements.ts:88-95` states the
rule as *"The FIGURES can still be changed — the deal is not signed yet (QA8-1)"*, and commit
`547f044` is titled *"a deal's figures can be edited while **nobody** has signed"*. Nobody-has-signed
is not what is enforced.

**Actual:** the gate is `canReviseTerms: authority.canManage && !frozen` where
`frozen = agreementStatus === "confirmed" || "signed"` (`apps/web/src/components/useEventAgreements.ts:161,184`),
and the server's gate is the same predicate (`agreementIsFrozen`, `apps/api/src/lib/deal-confirmation.ts:168`,
consumed at `apps/api/src/routes/deals.ts:879`). Both only become true once the **last** signatory
stamps — so the entire window between the first signature and the last is open for a unilateral rewrite.
The frozen snapshot then records:

```
guaranteeAmount "9000000"            <- written 2026-09-29 00:05 by the agent
parties[0] confirmedAt "2026-09-28T23:57:56.361Z" confirmedBy "e2e-operator"
frozenAt   "2026-09-29T00:08:27.655Z"
```

**Evidence:**
```
$ docker exec -i showme-e2e-postgres psql … -c "select version,guarantee_amount,agreement_status from deals where id='57900f02-…'"
 version | guarantee_amount | agreement_status
       3 |          6000000 | sent          <- after the operator signed
       4 |          9000000 | sent          <- after the agent's edit, operator's confirmed_at UNCHANGED
       5 |          9000000 | confirmed     <- after the agent signed
```
plus the `confirmed_snapshot` above, and `docs/screenshots/qa-2026-09-29-run11/09-share-export.png`
(the operator's own Deals tab afterwards: *"Confirmed — terms frozen · 2 of 2 signed · Fixed amount **SEK 90,000**"*).
The operator's Budget Planner immediately reads *"Performer fee SEK 90,000"*. **Verified twice** — at the
API/DB level and on both parties' screens.

**Scope:** direction-agnostic. The same control is on the operator's card, so an operator can raise
its own rental against an act that has already signed. Any deal with 2+ signatories.

## 5. Probes that lied

- **`element.click()` on a calendar day does nothing.** The first Mark-Unavailable attempt produced no
  row in `profile_unavailability` and I was one line from filing *"unavailability never saves"*. The
  cell is a pointer-event target: `aria-pressed` stayed `"false"` after a click and went `"true"` after
  a `pointerdown`/`mousedown`/`pointerup`/`mouseup` sequence. The feature works.
- **`fill` on a React-controlled number input appends.** Setting EST. SALES to `320` left the field
  holding **`0320`** and the row saved `est: 0`, which reads exactly like a save bug. Clearing with the
  native value setter first, then setting, stored `est: 320`. Mine, not the app's.
- **A flattened `innerText` moved a section heading.** On My Profiles the string *"Kept back for booking
  conversations / Off your public page / …An anonymous visitor never sees it"* prints directly under
  **AUDIENCE LOGISTICS**, and I had begun writing a MAJOR about the public profile endpoint returning
  `audienceLogisticsNotes` to an anonymous caller. It is the heading of the **next** group.
  `VENUE_FIELDS` (`apps/web/src/components/VenueDetailsFields.tsx:54-65`) marks `audienceLogisticsNotes`
  as `audience: "public"` and the industry tier starts at `amenities`. The endpoint is correct; the
  finding was withdrawn before it was written.
- **A 400 that was about my own typo.** `POST /events/:id/change-request` with `{"proposedDate", "note"}`
  answered *"Name a date, venue or room that is actually different"* — the schema's fields are
  `eventDate` / `reason` and Zod stripped mine, so the route saw an empty patch. Worth recording for the
  opposite reason too: the **crew** 403 on the same malformed body is still genuine, because
  authorization answers before the body is read.
- **`git rev-parse` at the end disagreed with the start.** HEAD moved from `a2aaf28` to `9c11ef2` under
  the sweep. Checked rather than assumed: the diff is one docs file, so no finding is measured against
  code the checkout has moved past.
