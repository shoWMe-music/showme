Budget Planner, Settlement & Deal Logic

How forecasting, deal terms and settlement calculation interlock in shoWMe. Code blocks are the shipped implementation.

1. The three stages

StagePurposeEditable
Budget PlannerForecast the night before it happens — ticket tiers, costs, deal terms. Produces break-even and projected P&L.Yes
Financials (settlement)Record what actually happened. Seeded from the planner, then corrected. Extra revenue/cost/deduction lines can be added or removed here.Yes
SettlementRead-only preview of entitlements and party payouts. Curated per collaborator, commented per line, then sent for approval.No
Planner is the baseline. Choosing “Start from Budget Planner” copies every tier, cost and deal term into Financials. The planner figures are retained so the settlement can show Planned vs actual deltas per line.

2. Deal structures

Deal typePerformer entitlementTicket revenue
GuaranteeFixed fee, regardless of turnout.All ticket revenue is the operator's. Performer carries no upside or downside.
Door SplitAgreed % of the door/net.Split by the percentages, no floor.
Guarantee vs Doormax(guarantee, split share) — the guarantee is a floor, the split is the upside.Below the crossover the operator absorbs the shortfall; above it the split governs.
RentalPerformer/promoter rents the room; venue takes a fixed rental.Belongs to the renter, less the rental fee.

Guarantee vs Door — worked example

Guarantee €1,000 Split 70 / 30 (performer / operator) Ticket revenue €1,000 split share = 1,000 × 70% = €700 entitlement = max(1,000, 700) = €1,000 ← guarantee floor applies operator keeps €0 and absorbs any costs → break-even or a loss Ticket revenue €2,000 split share = 2,000 × 70% = €1,400 entitlement = max(1,000, 1,400) = €1,400 ← split now exceeds the floor operator share = €600
The performer fee in Costs is derived, not typed. Once ticket revenue crosses the point where the split beats the guarantee, the performer cost line rises with it. The guarantee is always the minimum.

Three-way splits

Splits are independent shares of the adjusted net, expressed as percentages that total 100 across performer, promoter and venue. The promoter is not a residual claimant — each party's share is computed from the same pool, so no party silently absorbs rounding or shortfall. Percentages are shown next to every derived figure so the basis is always visible.

3. Waterfall order

  1. Gross revenue — ticket tiers + door + additional revenue + custom revenue lines
  2. less Deductions — ticketing fees, tax, refunds, production, additional and custom cost/deduction lines
  3. = Net revenue
  4. less Venue rental — taken off the top, before splits
  5. = Adjusted net — the pool the splits apply to
  6. Performer entitlement — per deal type, guarantee as floor, plus any performance bonus once its threshold is met
  7. Venue and promoter shares — their split percentages of the adjusted net

4. Break-even

Break-even is the ticket count where revenue meets total cost. The planner graph plots both lines and shades the space between them — green above the crossover (profit), red below (loss). Hovering reads off revenue, cost and margin at any ticket count while the calculated break-even marker stays pinned.

revenue(t) = Σ(tier price × tickets sold) + bar/F&B + other cost(t) = fixed costs + performer entitlement(t) + per-ticket fees × t break-even = smallest t where revenue(t) ≥ cost(t)
Because the performer entitlement itself moves with revenue under Guarantee vs Door, the cost line is not flat — it steps up once the split overtakes the guarantee. That kink is where operator margin stops growing linearly.

5. Visibility rules

Operators see every figure. Collaborators see only what concerns them, and the operator can curate this line by line.

RoleSees by default
OperatorEverything — all revenue, all costs, every party's payout
PerformerOwn deal terms and entitlement, ticket revenue, merchandise (if in deal), share of bar/food (if in deal)
VenueOwn deal and rental, ticket revenue, bar/food revenue

Curation is per role and per line, including custom lines. A hidden line is simply absent from the collaborator's settlement — no placeholder is shown, because the existence of, say, a venue's own cost is not the performer's business.

6. Approval and comments

Every line carries its own comment thread; operator and collaborators can both post, attributed with name, role and time. Settlements are sent for review per collaborator, so each party receives only their curated view. Each records its own approval, and a request for changes moves the settlement back to comments_received for revision.

7. Implementation — settlement engine

compute(e){
    // Implements handoff Section 7.4 — party splits are independent, promoter is NOT residual.
    const d=e.deal, r=e.rev, n=this.n.bind(this);
    const xs=(e.sdExtras||[]);
    const xRev=xs.filter(x=>x.kind==='revenue').reduce((a,x)=>a+n(x.amount),0);
    const xDed=xs.filter(x=>x.kind!=='revenue').reduce((a,x)=>a+n(x.amount),0);
    const totalRevenue = n(r.gross)+n(r.door)+n(r.additionalRevenue)+xRev;
    const totalDeductions = n(r.ticketFees)+n(r.tax)+n(r.refunds)+n(r.production)+n(r.additionalCosts)+xDed;
    const netRevenue = totalRevenue - totalDeductions;
    const venueRental = n(d.venueRental);
    const adjustedNet = netRevenue - venueRental;
    const doorShare = adjustedNet * n(d.artistSplit)/100;
    let artistBase, basis;
    if(d.dealType==='guarantee'){ artistBase=n(d.guarantee); basis='Flat guarantee'; }
    else if(d.dealType==='door_split'){ artistBase=doorShare; basis=n(d.artistSplit)+'% of adjusted net'; }
    else if(d.dealType==='guarantee_vs_door'){
      if(doorShare>=n(d.guarantee)){ artistBase=doorShare; basis=n(d.artistSplit)+'% door beats \u20ac'+n(d.guarantee).toLocaleString('en-US')+' gtee'; }
      else { artistBase=n(d.guarantee); basis='\u20ac'+n(d.guarantee).toLocaleString('en-US')+' gtee beats '+n(d.artistSplit)+'% door'; }
    } else { artistBase = n(d.guarantee)>0?n(d.guarantee):doorShare; basis='Rental deal'; }
    let bonus=0, bonusEligible = n(d.bonusThreshold)>0;
    if(bonusEligible && totalRevenue>=n(d.bonusThreshold)) bonus=n(d.bonusAmount);
    // Section 7.4: each party = adjustedNet * theirSplit% (independent); venue also keeps the rental.
    const venuePool = adjustedNet * n(d.venueSplit)/100;
    const promoterPool = adjustedNet * n(d.promoterSplit||0)/100;
    const venuePayout = venueRental + venuePool;
    const artistPayout = artistBase + bonus;
    const promoterPayout = promoterPool;
    // The margin promoter retains after paying artist above their pool (visibility only).
    const promoterMargin = adjustedNet - artistBase - venuePool - bonus;
    return { totalRevenue,totalDeductions,netRevenue,venueRental,adjustedNet,artistBase,doorShare,basis,bonus,bonusEligible,venuePool,promoterPool,venuePayout,artistPayout,promoterPayout,promoterMargin };
  }

8. Implementation — budget planner

computeBudget(e){
    const b=e.budget||{}, n=this.n.bind(this);
    const tickets=b.ticketTypes||[];
    const ticketRev=tickets.reduce((s,t)=>s+n(t.price)*n(t.qty),0);
    const soldTickets=tickets.reduce((s,t)=>s+n(t.qty),0);
    const revLines=b.revLines||[];
    const otherRev=revLines.reduce((s,r)=>s+this.revLineTotal(b,r,soldTickets),0);
    const legacyRev=n(b.avgBar)*n(b.capacity)+n(b.otherRev)+(b.customRev||[]).reduce((s,x)=>s+n(x.amount),0);
    const totalRev=ticketRev+otherRev+legacyRev;
    const costLines=b.costLines||[];
    const cashCosts=costLines.reduce((s,c)=>s+this.costLineAmount(e,c,ticketRev),0)+(b.customCost||[]).reduce((s,x)=>s+n(x.amount),0);
    const ppFees=ticketRev*n(b.ppFeePct)/100 + n(b.ppFeeFlat)*soldTickets;
    const totalCost=cashCosts+ppFees;
    const profit=totalRev-totalCost;
    const avgP=soldTickets?ticketRev/soldTickets:0;
    const perGuest=revLines.filter(r=>r.basis==='guest').reduce((s,r)=>s+n(r.amount),0);
    const flat=revLines.filter(r=>r.basis!=='guest').reduce((s,r)=>s+n(r.amount),0)+legacyRev;
    const varCost=avgP*n(b.ppFeePct)/100+n(b.ppFeeFlat);
    const contribution=avgP+perGuest-varCost;
    const fixed=cashCosts-flat;
    const beRaw=contribution<=0?Infinity:Math.ceil(fixed/contribution);
    const beInfinite=!isFinite(beRaw)||beRaw<0;
    const margin=totalRev>0?profit/totalRev*100:0;
    return {ticketRev,soldTickets,otherRev,barRev:legacyRev,totalRev,cashCosts,ppFees,totalCost,profit,margin,
      breakEven:beInfinite?0:beRaw, beInfinite, beContribution:contribution, beFixed:fixed, beAvgP:avgP, bePerGuest:perGuest, beFlat:flat, beVarCost:varCost,
      revPerGuest:soldTickets?totalRev/soldTickets:0, costPerGuest:soldTickets?totalCost/soldTickets:0, cap:n(b.capacity)};
  }
